Для встановлення та налаштування Tailwind CSS у проєкті Vue 3 (з використанням Vite) були виконані наступні кроки, згідно з інструкціями:

1. Встановлено Tailwind CSS та офіційний Vite plugin за допомогою команди npm install -D tailwindcss @tailwindcss/vite.

2. Відкрито файл vite.config.js і додано імпорт tailwindcss та його виклик у масив plugins.

3. Створено файл src/assets/css/index.css і додано в нього імпорт @import "tailwindcss"; (для Tailwind v4).

4. У файл src/main.js додано імпорт CSS-файлу: import "./assets/css/index.css";.

5. Видалено старі <style scoped> та замінено вміст компонента, додавши класи Tailwind для головної навігації (<header> та <nav>):

Клас для центрованого контейнера: class="max-w-4xl mx-auto".

Класи для навігації: class="p-4 bg-gray-100 rounded-b-lg shadow-md".

6. Видалено старий клас .contact-page і замінено його на утиліту Tailwind p-5 для відступу.




2. Поясніть, як реалізували умовні стилі (для isActive) у UserCard.vue за допомогою класів Tailwind.



Умовні стилі були реалізовані безпосередньо в шаблоні компонента UserCard.vue за допомогою директиви :class та логіки Vue (тернарний оператор).

Замість того, щоб у CSS визначати класи .active та .inactive, ми динамічно застосовуємо готові утиліти Tailwind, які відповідають бажаному стану.

Принцип реалізації:

Перевіряється значення пропсу isActive (тип boolean).

Якщо isActive є true, застосовується набір класів для активного стану (наприклад, border-green-500 bg-green-50).

Якщо isActive є false, застосовується набір класів для неактивного стану (наприклад, border-gray-300 bg-white).

Цей підхід дозволив повністю усунути необхідність у локальному CSS для компонента та реалізовувати умовне стилізування в одному місці.

3. Які переваги та недоліки utility-first підходу (Tailwind) ви помітили порівняно з <style scoped>?

Переваги (Порівняно з <style scoped>)
Відсутність перемикання файлів: Стилізація відбувається безпосередньо у шаблоні (<template>), усуваючи необхідність постійно перемикатися між HTML та блоком <style scoped> або окремим файлом CSS.

Швидкість розробки: Стилі застосовуються швидше, оскільки не потрібно вигадувати назви для класів, що значно прискорює ітерацію дизайну.

Консистентність: Використання фіксованого набору утиліт (наприклад, p-4, shadow-md) забезпечує єдність у відступах, тінях та кольорах, що часто є складним завданням при написанні чистого <style scoped> CSS.

Простота умовних стилів: Умовні класи, як і підтримка темної теми (dark:), легко реалізуються вбудованими засобами Vue, тоді як у <style scoped> це вимагало б написання повних CSS-правил для кожного стану.



Недоліки (Порівняно з <style scoped>)
Засміченість розмітки: Найбільш помітний недолік — це менша читабельність шаблону. Довгі рядки класів (наприклад, class="max-w-4xl mx-auto mt-5") ускладнюють швидке сприйняття структури HTML/Vue, тоді як <style scoped> дозволяє мати чистий HTML з кількома семантичними класами.

Крива навчання: Потрібен час для запам'ятовування назв класів-утиліт Tailwind, тоді як <style scoped> використовує стандартний CSS.
